# Personal name in introductions

The selected profile name already reaches GPU vocabulary and the local decision request's me field. That is a decoding/ranking hint, not a guarantee that the intended name exists in the returned candidates. Rare names may still be decoded as ordinary words; Jev reranks candidates and cannot recover an absent spelling reliably, especially with the decision service disabled.

The client now offers one labeled saved-name correction when a top-three candidate explicitly begins with "my name is" (optionally preceded by hi/hello/hey). It substitutes only a bounded apparent name span with the current profile's spelling and preserves the candidate's remaining text. Original decoder candidates stay available. It does not rewrite arbitrary mentions, "his name is", or every unknown word, and it does not claim to fix hallucinated trailing clauses. The correction has no invented lip score or probability and uses a choose route. The full and compact widgets label it as a saved-name correction. Clicking or the existing explicit confirmation gesture is still required to speak it; it remains available without Jev/Claude and does not change the shared server protocol.

Saving profile settings also calls the existing ensureOwnName helper so a valid name is retained in the local vocabulary and sent during enrollment. No specific user's name or automatic misreading aliases are hard-coded. Existing training, keys and environment files are unchanged. No tests, builds, app launches or live service requests were run for this change, per the user's standing instruction. This improves a narrow self-introduction case; names and the rest of unrestricted speech remain subject to recognition errors.
